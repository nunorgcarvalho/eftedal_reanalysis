eftedal_reanalysis — how the code works

A guide to what every part of the code computes and why, for answering questions about the analysis and for checking it. Function names are given as module.function under src/eftedal/.

At a glance

Eftedal et al. (2025, PNAS) published 82 phenotypic correlations between categories of Norwegian relatives (twins to 2nd cousins, step siblings, "co-cousins", adoptive relatives) for school test scores. Each category has one correlation \(\hat\rho_k\) with a standard error \(SE_k\). We fit models that predict every \(\rho_k\) from how much the pair shares genetically (under assortative mating) and environmentally, and ask how the conclusions depend on modelling and fitting choices.

The whole analysis in one line: choose a model (which components), predict all 82 correlations as a function of a few parameters, and find the parameters that minimise a weighted sum of squared differences between observed and predicted correlations. Everything else is about which weights, which components, and how sure we are.

Data

What the files contain

data/eftedal_osf/correlations/ holds the authors' public OSF files: for each of 13 phenotypes, 82 rows of aggregate statistics: corr, SE, number of pairs, and labels (rel = relationship type, type = maternal/paternal/other, pair = sex composition). No individual-level data. The main phenotype is MRE8 (average of the 8th-grade math, Norwegian and English tests).

Cohorts and data checks

data.COHORTS: ALL (82, the main analysis), ALL_but_adopted_UZ (Eftedal's "bio + in-law", 53), bio_only (41). data.load() flags one row as suspect_duplicate: in every non-adoptive OSF file, 2nd cousins / other / same-sex female is an exact copy of 2nd cousins / paternal / same-sex female. It is kept by default; dropping it changes nothing material.

The model

For category \(k\), with \(\theta\) the parameters, the prediction is

\[ \rho_k(\theta) \;=\; \Big[\, V_A\,K_k + V_{GxG}\,K^{(2)}_k + V_{house}\big(h^{full}_k + \pi\, h^{part}_k\big) + V_{fam}\, r_f^{\,f_k} \Big]\,\big(1 + \delta\, M_k\big) \]

Each model includes a subset of the bracketed terms. The maternal factor \(\delta\) is implemented but not used in the main analysis (set aside as post hoc and uninformative). Implemented in model.Model.predict; the per-component contributions are returned by model.Model.components.

Genetic sharing under assortative mating

\(K_k\) is the expected genotypic correlation of the pair under primary phenotypic assortative mating at equilibrium (Fisher's model; Eftedal et al. Table S9). With \(m\) the genetic correlation between mates and \(r\) the phenotypic correlation between mates (components.genetic_kernels):

category\(K_k\)
MZ, DZ, full sibs, 1st and 2nd cousins (n = 0, 1, 1, 3, 5)\(\left(\frac{1+m}{2}\right)^{n}\)
via twins of unknown zygosity (UZ twins, 1st/2nd cousins t/uz)\(p\left(\frac{1+m}{2}\right)^{n-\frac12} + (1-p)\left(\frac{1+m}{2}\right)^{n+\frac12}\), MZ fraction \(p = 0.5\)
half sibs (n = 2), half cousins (n = 4)\(\left(\frac{1+m}{2}\right)^{n}\,\frac{1+2m+rm}{(1+m)^2}\) (Nagylaki's multiplier)

co-cousins\(m\left(\frac{1+m}{2}\right)^{4}\)
adoptive pairs0
Why the step-sibling formula changes

Step siblings are connected through a chain of three matings (one parent of A is mated to one parent of B). Along a mating chain, the first step costs the genetic mate correlation \(m\), and every further step costs the phenotypic correlation \(r\), because assortment acts on phenotypes. Averaging over the four parent pairs gives \(m\left(\tfrac{1+r}{2}\right)^2\). Eftedal's expression prices every step at \(m\). That is inconsistent with their own half-sibling multiplier, which prices a two-step crossing at \(rm\). Derived in popstatgenwriteups, relative_covariance v1 and its eftedal note. The two forms agree when \(r = m\).

Coupling \(m\) and \(r\). Under primary phenotypic assortment at equilibrium, mates' genetic values correlate through their phenotypes: \(m = h^2 r\), where \(h^2 = V_A\) on the correlation scale. The main analysis imposes this (FitSpec.mr = 'equilibrium'; model.Model.unpack sets \(m = V_A r\)), so \(r\) is estimated and \(m\) derived. Eftedal et al. estimate them separately (mr = 'free').

GxG. \(K^{(2)}_k = K_k^2\): a pairwise interaction is shared only if both loci are shared. For UZ-linked categories, both kernels are averaged over the MZ/DZ alternatives. This form is assumed, not derived under assortative mating.

Parameters and constraints

  • Box bounds: everything in \([0,1]\) except \(\delta \in [-0.5, 1]\) (model.PARAM_BOUNDS).
  • \(V_A + V_{GxG} + V_{house} + V_{fam} \le 1\) (FitSpec.max_total_variance). Phenotypic variance is 1, so this keeps the residual variance \(V_E \ge 0\). Without it, some rich models reached \(\sum V \approx 1.2\) (a predicted MZ correlation above 1).
  • Main settings (presets.MAIN, presets.main_spec): linear scale, \(m = V_A r\), corrected step-sibling kernel, co-cousin \(f = 2\), \(\sum V \le 1\), UZ mixture at 0.5; weightings hybrid_block (primary) and invvar.

Estimation

Parameters minimise the weighted residual sum of squares over the categories in the cohort (model.Model.loss):

\[ L(\theta) = \sum_k w_k\,\big(\hat\rho_k - \rho_k(\theta)\big)^2 . \]

Weights: what each one estimates

weighting\(w_k\)what it targets
invvar\(1/SE_k^2\)If the model were correct (and categories independent), this is the Gaussian maximum-likelihood fit, the most precise possible. Under misspecification it is the best fit for a typical pair: dominated by cousins and co-cousins, because there are millions of them.
hybrid_block (main)\(\dfrac{1/SE_k^2}{\sum_{j \in b(k)} 1/SE_j^2}\)Every block \(b\) of relationship types (the 10 cv blocks) gets total weight 1, split within the block by precision. The best fit for a typical kind of relative. Near-duplicate types (e.g. 1st cousins and 1st cousins via UZ twins) share one block's weight instead of each getting a full share. Moves leverage toward close relatives (the twin block gets 1/10 of the total).
hybridsame, balanced over the 16 relationship typesthe 2025 poster's version; not used in the main analysis

If the model were right, every weighting would estimate the same parameters, and only the precision would differ. That they disagree is itself evidence of misspecification (\(\chi^2/\text{df} \approx 9\)–\(51\) across the 8 core models). Implemented in model.Model._weights.

Why not the log scale (and what Eftedal et al. got wrong)

Eftedal et al., following Clark, fit \(\ln\rho_k\) because the Fisherian model is then linear in its parameters. They weighted each log-correlation by \(1/SE_k^2\), but \(SE_k\) is the standard error of \(\hat\rho_k\), not of \(\ln\hat\rho_k\). By the delta method,

\[ \operatorname{Var}(\ln\hat\rho_k) \approx \frac{SE_k^2}{\rho_k^2}, \qquad\text{so the consistent weight is } \frac{\rho_k^2}{SE_k^2}. \]

Their choice multiplies each category's weight by \(1/\rho_k^2\): about ×200 for 2nd cousins (\(\rho \approx 0.07\)) against ×1.3 for MZ twins. That is why distant relatives dominate their fit and give \(h^2 = 0.50\). With a general optimiser there is no reason to log-transform, so the main analysis uses the linear scale. The log scale with delta-method weights (scale='log', weights='invvar') is kept as a robustness row.

How the optimisers work

The loss \(L(\theta)\) is a surface over 3–8 parameters. There is no closed-form minimum, so every method starts somewhere and walks downhill until it can no longer improve. Implemented in fit.fit, fit._local_search and fit._polish (all from scipy.optimize.minimize).

L-BFGS-B: the main local search (box bounds only)

A quasi-Newton method. At the current point it estimates the gradient by nudging each parameter slightly (finite differences). It also keeps a running estimate of the surface's curvature, built from the last few steps ("limited-memory BFGS"). The curvature turns "which way is downhill" into "how far to step", so it converges far faster than plain steepest descent. Bounds are handled by projecting: a parameter that wants to leave \([0,1]\) is held at the edge, which is how \(r\) ends up "at bound 0".

SLSQP: when the variance-sum constraint is on

Sequential least-squares quadratic programming. At each step it approximates the loss by a quadratic bowl and the constraint \(\sum V \le 1\) by a straight line, solves that small problem exactly, steps, and repeats. Used for every main-analysis fit with at least one variance component.

Powell and Nelder–Mead: derivative-free polish

Powell does one-dimensional line searches along a set of directions and updates the directions as it goes. Nelder–Mead moves a simplex (a cloud of \(p+1\) points) by repeatedly reflecting, expanding or shrinking its worst point. Neither needs gradients, so both cope with kinks. They are run from the two best local solutions; any constraint violation is penalised, and the result is finished with the constrained local search.

The optimisers used before (Eftedal et al.; 2025 code)

R's nloptr: SBPLX (Eftedal) is a Nelder–Mead variant on subspaces. COBYLA and BOBYQA (2025 code) are derivative-free methods that fit linear (COBYLA) or quadratic (BOBYQA) models to function values inside a trust region. All are local methods with a stopping tolerance.

Local vs. global, and how we check convergence

Every method above finds a local minimum and stops when improvement falls below a tolerance, which can be premature on flat ridges. fit() therefore runs a multi-start: the 2025 starting values plus n_starts random starts (12–20), polishes the best two, and keeps the lowest loss. It records n_converged_to_best, the number of starts that reached the best loss within \(10^{-6}\). If most agree, a hidden better valley is unlikely. at_bound lists parameters sitting on a bound.

Failures seen in this project. (1) The 2025 BOBYQA fits stopped at local optima in 2 of 32 cases (we find 10–21% lower losses). (2) The 2025 COBYLA fits left \(r\) near its start value of 0.5, because the loss is nearly flat in \(r\). (3) Eftedal's SBPLX solution (0.503) sits slightly short of the optimum (0.500) on a flat ridge. (4) The 2025 log-scale code dropped rows predicted below \(10^{-4}\). That gave the loss a fake global minimum of 0 at \(V_A = 0\), and BOBYQA "found" solutions just under the cut-off. The new code removes this (log_zero='structural').

Two-step (sequential) estimation of GxG

FitSpec.sequential_base fits a base model first, then the full model with the sequential_carry parameters held at their step-1 estimates (fit._fit_sequential). The core A→GxG models use base A and carry \(V_A\) and \(r\) (hence \(m\)): the additive contribution to every correlation is exactly that of model A, and step 2 fits GxG and any environment term to what A leaves over. The result keeps the sequential spec, so the jackknife, cross-validation and bootstrap redo both steps; degrees of freedom count both steps' parameters. Wald/sandwich covariances would be conditional on step 1 and are not used.

What it does and does not estimate. This is the summary-statistic version of sequential (type I) sums of squares: with collinear terms, whichever enters first absorbs the signal they share. Two-step \(V_{GxG}\) is therefore "the GxG-shaped signal the best additive model cannot mimic", not \(V_{GxG}\) under the joint model. On these data it is ≈ 0.01–0.02 (0 next to H or F), against ≈ 0.22–0.35 when fitted jointly (supplement), and the profile over \(V_A\) puts the two-step \(V_A\) outside the 95% quasi-likelihood cut-off of the joint models. Both are reported; the joint split is poorly identified (the profile valley), the two-step split is a convention.

Model comparison: block cross-validation

For each of the 10 cv blocks: refit without the block, predict its categories, score the error (cv.cross_validate). Two group tests hold out several blocks at once: all in-laws (Eftedal's bio-only → in-law test) and all adoptive pairs. The scoring was fixed before looking at results:

\[ \text{mse}_t = \frac{\sum_{k\in t} (\hat\rho_k - \hat\rho^{\,cv}_k)^2/SE_k^2}{\sum_{k\in t} 1/SE_k^2},\quad \text{block score} = \operatorname{mean}_{t \in \text{block}}\, \text{mse}_t,\quad \text{CV score} = \operatorname{mean}_{\text{10 blocks}}\, \text{block score}. \]

The score is in squared-correlation units (a precision-weighted mean squared miss of held-out correlations); its square root, the CV RMSE, is in correlation units. A held-out \(\chi^2\) is also reported. Models are compared fold by fold (cv.paired_comparison): for each model, take its score minus the best model's in each of the 10 blocks, and report the mean difference with SE = SD/\(\sqrt{10}\) of those 10 differences. The SE is approximate: the folds share training data, and 10 heterogeneous blocks is a small sample.

Caveats. Sampling errors are correlated across categories (the same child appears in sibling, cousin and co-cousin pairs), so CV is slightly optimistic. But sampling SEs (~0.003–0.01) are small next to the misfit being scored. Near-duplicate types are held out together to avoid leakage. A component identified by a single block (e.g. \(\pi\) by step sibs + paternal half sibs) is unconstrained when that block is held out, so read the per-block errors, not only the total.

Assumptions, limitations, and questions you might get

"Why not fit log-correlations, like Clark and Eftedal?"
That was a fitting convenience: it makes the model linear. With a general optimiser it isn't needed, and their weights were wrong for the log scale (delta method above). With consistent weights, log and linear fits nearly agree. Their remaining gap reflects misspecification.
"Isn't hybrid weighting arbitrary?"
It is a choice of estimand: the best fit for a typical kind of relative rather than a typical pair. Under a correct model it would not matter. Under misspecification no weighting is "right", which is why both are reported. Balancing over blocks rather than over the 16 types avoids double-counting near-duplicate types. In block cross-validation the two weightings trade wins: inverse variance is slightly better for the models without GxG, block hybrid for the GxG + family models (all within ~3 SE).
"Why impose \(m = h^2 r\)? Collado et al. did and got different answers from Clark."
Separate \(m\) and \(r\) make sense if people sort on a latent trait rather than on the phenotype. But then the half- and step-sibling formulas (derived for phenotypic assortment) are wrong too. With consistent weights the constraint costs almost no fit (additive model, inverse variance: \(\chi^2/\text{df}\) 25.91 vs 25.93 with \(m, r\) separate) and implies \(r \approx 0.3\)–\(0.5\) (0.32 block hybrid, 0.39 inverse variance, 0.47 log scale), a plausible spousal correlation. Under Eftedal's weighting it would need \(r \approx 0.87\).
"Your bootstrap intervals are tiny. Is the model right?"
No. The bootstrap only measures sampling noise in 82 very precise correlations. Model misspecification shows up in the block jackknife and in the spread across weightings and models, which are far larger.
"Are the 82 correlations independent?"
No: individuals appear in several pairs and categories. Eftedal et al. estimate their CIs are <30% too narrow, and re-running the bootstrap with SEs ×1.3 barely changes the intervals.
"Is GxG = \(K^2\) justified under assortative mating?"
It is an assumption (exact without assortment for pairwise interactions, approximate with it). Derivation is ongoing (popstatgenwriteups).
"Can you separate a family environment from assortative mating?"
Only partly. Both predict similarity that decays with distance; under inverse-variance weights the family-environment model can drive \(m \to 0\). Adoptive relatives (environment without genes) are the only anchor, which is why the "all adoptive" hold-out is informative.
"Why does the household term not help?"
In cross-validation, sibling-only household terms predict held-out types worse (2–3 SE). They absorb the sibling excess, which lowers \(V_A\) and \(m\), and the model then under-predicts cousins (e.g. held-out 1st cousins by ~0.055 under block-hybrid weights). A family environment that decays over the whole tree generalises better.
"Does the corrected step-sibling formula matter?"
Barely for the parameters (step siblings are 3 of 82 categories, ~0.3% of pairs): the additive \(h^2\) moves by \(\le 0.002\). It does raise the predicted step-sibling correlation itself (e.g. 0.087 → 0.101 under inverse variance), toward the observed 0.127, but not all the way.
"Why fit the additive part first and add GxG on top?"
It answers "is there GxG-shaped signal the additive model cannot already explain?" On these data the answer is essentially no (\(V_{GxG}\) ≈ 0.01–0.02). It is not an estimate of how much variance GxG would take under a joint model (≈ 0.3, poorly identified): whichever term enters first absorbs the shared signal. The supplement shows both, and the \(V_A\) profile shows the trade-off.
"Which model fits best?"
By block cross-validation, every model containing the decaying family environment forms a top cluster whose members are within ~1 SE of each other. Among the core models A+F is best under both weightings; in the all-joint set A+GxG+F scores best under block hybrid. Additive-only is ~1–2 SE behind, and sibling-household models without F are clearly worse. So the data support some family-wide environment, but cannot cleanly tell whether GxG is also present.
"Twins of unknown zygosity at 50% MZ?"
Eftedal's assumption; registry ratios suggest ~42% recently. Rerunning at 0.42 changes \(h^2\) by ≤ 0.011.
"What about selection (people with half or step siblings score lower)?"
Not modelled, as in Eftedal et al. (their SI Table S10). A limitation.
